# ADR-0030：原图总预算与串行分组传输

日期：2026-10-07（Asia/Taipei）。状态：采纳。关联 R02/R08/R34、K04/K08、C26。

## 背景

v1.1.2 的工具结果包含七处视觉证据，因旧 Run 引用注册表固定四图上限返回 RUN_IMAGE_BUDGET_EXCEEDED，未发送原图。聊天能力判断也只读取旧 image 标签，与 endpoint IMAGE 不一致。用户确定总上限 64 张、单次 8 张，并要求分组串行、组内并行。

## 决定

1. 未指定 imageBudget 时，Run 原图总预算为 64，显式 1—64 张配置保留；单次请求最多 8 张、原始字节最多 16 MiB，每张最多 2 MiB。以上是本地保护值，不代表任一 Provider 保证支持。来源以 asset、媒体类型、内容哈希去重；超过总预算明确停止。
2. 自动检索、历史及工具先提供经过授权检查的 CAS 元数据引用。只在当前组内并行读取和编码原图，复核来源、哈希与大小；不会为 64 张保留全部 Base64。每组使用同一选定模型和凭据单独分析，工具禁用，待明确成功才发送下一组。分析内容按来源标识包装为不可信证据，再交给主请求综合。每组真实请求都计入 Run 请求、时间、输入和用量预算。
3. 成功批次保存来源哈希与证据记录；后续请求使用记录而不重复原图。历史投影仍复核来源授权及当前哈希，内容变化必须重新读取。每组派发前再次复核授权，预览或持久化期间撤权也阻断派发。未知、取消、Provider失败不自动重播；部分成功记录保留。
4. 使用 ModelProfile.acceptsImages() 统一 endpoint IMAGE 与旧 VISION/image 语义。不猜测模型名称能力，不切换 Provider。工具卡保留具体降级警告，成功批次显示已传输张数；文本模型、显式降级、缺失/超大图仍明确披露。
5. 2026-10-07 输出预算修正：每组分析继承主请求已解析的输出预算、字段别名和完整参数层。AUTO 不另加输出 token 上限，手动较小上限也不擅自抬高；不得清空用户的 thinking/reasoning、采样或响应格式配置。简短证据以提示词和现有 16,000 字符正文上限约束，JSON 响应格式明确要求 JSON。空 JSON 结构/null/全空白叶在成功事件及记录之前拒绝，数字 0、布尔 false 和非空文字保持有效。推理和正文共享供应商的输出预算，Provider失败仍停止且不自动重放；正常完成后的本地证据拒绝按下述2026-10-08有界规则恢复。

## 替代方案与影响

只提高为 64 张单请求会扩大内存、请求体和窗口风险；保留四图限制无法满足需求。串行分组会增加模型请求数和延迟，独立图片分析不能保证保留所有细节；最终回答必须沿来源标识核对证据，不能宣称看过未提供的图。原始 CAS 图片保持可追溯。

保留 ADR-0010 完整预算和 ADR-0027 工具批次配对、推理续轮及隐私契约。无数据库迁移或 Provider 协议新增字段。测试、独立审查及发布结果见 [本轮证据](../evidence/2026-10-07/visual-transfer.md)。真实 Provider 接收/理解、实体手机升级分别验收。

v1.1.3 的六图分析推理预算耗尽及 v1.1.4preview 本地候选验证另见 [输出预算修复证据](../evidence/2026-10-07/visual-analysis-output-budget.md)，不回写已发布 v1.1.3 的验证状态。

## 2026-10-08：完成回执的有界精简恢复

HTTP 200且完整流正常结束后，图片分析正文超出16,000字符或为空证据结构，属于本地已知拒绝。只对该专用类型进行恢复：按原来源将当前组二分，8→4→2→1；单图仍无有效回执时，最多再请求一次更精简的证据，之后明确失败。每次保留选定模型、参数层、手动输出别名和AUTO，每次重新检查授权、来源及输入预算，并计入同一Run的请求/时间/usage。完全细分8图最多23次分析，Run预算可更早停止，不扩大64张唯一来源总预算。

已完成但被本地拒绝的尝试清除模型在途标记；它没有成功收据，也不向主回答交付截断文字。成功子组及时持久化，后续子组失败仍保留；知识工具不会重执行。只有完整drain、正常Completed且无Failed/拒绝/工具调用时才触发。断流、协议错误、结果未知、取消及Completed后传输异常均不自动重试。证据见[本轮调查与回归](../evidence/2026-10-08/knowledge-query-and-release-regression.md)。
