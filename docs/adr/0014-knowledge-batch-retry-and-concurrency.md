# ADR 0014：知识库批次自动重试与有界并发

日期：2026-09-27（Asia/Taipei）。状态：本地实现，独立只读复核 PASS，待设备验收。

## 背景

本次诊断包中四次视觉请求均在派发后约 180 秒成为 `vision_unknown`；同批次另有十八次视觉请求成功。普通 Provider 的 180 秒传输上限不适合长视觉处理。一次图片能力探测得到 `partial`/HTTP 4xx，原测试图片仅 1×1 像素，可能被多模态处理器拒绝。诊断包没有服务端响应正文，不能把 4xx 的精确原因断言为图片尺寸。

## 决定

视觉调用使用独立的 600 秒 HTTP 超时，普通 Provider 请求保持原预算。图片探测使用 128×128 PNG，仍以实际端点应答为准；图片探测收到泛化 HTTP 4xx 时记录为未知，而非宣称模型不支持图片。先前已保存的探测状态需重新执行探测才会刷新。

已确认固定视觉目标与资料范围的导入批次，对暂时性超时、限流、断网和 `UNKNOWN_OUTCOME` 自动重试，最多六次处理，WorkManager 持久退避。用户已明确接受可能重复计费。每次重试保存 attempt，成功结果继续按 cache key 复用。进程恢复先把可能已派发的尝试归为 UNKNOWN，随后按同一授权范围重试；失败、暂停、阻塞和取消批次都结清遗留派发槽，但已停止批次不自动重启。显式取消先持久化取消意图再停止 WorkManager；目标变化及确定性错误保持阻断。重试耗尽显示最后原因和次数。普通查询、工具调用及单文档门禁不受此决定影响。

不同文件最多三路处理，API Embedding 保持单路。SQLite 与索引变更仍串行。Schema v27 移除 v24 的单请求唯一索引，新增 1–3 号持久派发槽和活动槽唯一约束；迁移时旧库最多一个在途请求，将其归入槽 1。新批次默认三路，已有批次保存的策略值不被静默改写，用户可在处理限制中选择一至三路。未授权且可能含图的批次先单路检查首个视觉边界，避免后续成员越过阻断点。

## 替代方案及代价

维持单请求唯一索引不能提高大量文件吞吐；完全移除数据库并发约束会让多实例绕过内存计数。三个持久槽使每次派发仍有数据库唯一性约束，代价是视觉 Provider、设备网络与内存可能同时承受三项请求。六次重试允许重复计费且可能延长失败反馈时间，已按用户本轮选择记录；确定性失败及授权变化不消耗这项重试预算。

## 验证边界

JVM 测试覆盖三路真正重叠、槽占用与释放、未知结果重试上限、进程恢复、成功页复用及旧 schema 迁移。Android 编译与实际设备批量导入、后台杀进程、视觉服务长响应分别记录；编译或模拟测试不等于设备验收。
