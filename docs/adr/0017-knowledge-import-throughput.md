# ADR 0017：知识库导入吞吐与 PDF 局部证据

日期：2026-09-29（Asia/Taipei）。状态：本地实现与独立只读复审通过；真实 Provider 和设备验收未执行。

## 背景

用户的 294 个 PDF 共有 11,896 页。v19 的离线解析估计约 2,630 次视觉请求；诊断包中 ZIP 暂存约 7.7 秒，而 3 份文档的 29 次视觉派发历时约 13.5 分钟。Provider 响应是当前最显著的耗时来源。此前跨文档至多三路，单文档内部仍逐单元串行，原生文字分块与嵌入也在全部视觉结果之后才开始。另有两份空密码 Standard V4/R4 文件共 536 页因内容流未解密而走整页视觉；实际调用的 Form XObject 也被保守地视作未知图像来源。

## 决定

- 在同一文档内有界处理独立视觉单元，使用持久单元结果和派发 attempt 恢复；到达派发容量时等待。任一单元失败或仍未知，文档的 READY 及 active generation 发布屏障不越过。
- 同视觉处理重叠准备原生文字和本地向量。API Embedding 仍需独立授权且维持原有同库独占，不因视觉授权而提前外发文本。
- Schema v28 将持久派发槽从三路扩为六路；新批次默认四路，可在一至六路内配置。迁移为未显式保存策略的旧批次补存旧默认三路，显式策略保持原值。新上限是资源保护边界，实际最优并发需真机与 Provider 实测。
- 对能通过空密码认证的 Standard Security V4/R4 PDF 解密受支持的内容流；对实际调用的 Form XObject 递归提取可证明的文字、图片与页面操作。Form 字体未显式设置或外观受不可见文字、裁剪等未知状态影响时，不把该 Form 字串纳入原生索引并保留整页视觉。无法认证、密码不符、循环/畸形资源、未支持的过滤器或无法证明完整的外观继续视觉或明确阻断。
- 本轮不做多图合批、专用更快视觉模型和跨进程重复图片缓存。

## 一致性与资源取舍

页级任务能缩短长文档尾部等待，但同时渲染多页与扩大 Provider 在途请求会增加瞬时内存、带宽与限流压力，因此仍需批次策略、全局持久槽和单文档局部上限。保存成功结果要先于下一次恢复；暂停与授权变化只阻止新派发，已经返回的明确成功仍可落盘。旧批次保留旧并发值，避免升级后在用户未调整的情况下突然增加在途请求。

## 验证边界

验收用例见 [ACCEPTANCE 的吞吐与 PDF 补充项](../ACCEPTANCE.md#2026-09-29-知识库导入吞吐与-pdf-解析补充验收)，本地验证见[专项证据](../evidence/2026-09-29/knowledge-import-throughput.md)。本地假后端、离线语料与严格构建结果不等于真实 Provider 或物理设备的整包耗时验收。
