# ADR-0002：独立软件页面 UI 设计阶段

- 状态：已采用阶段安排；M0.5 UI 设计基线与双语支持已交付并获用户确认（DOC_CHECK_PASS）
- 日期：2026-08-28
- 来源：用户明确要求在 M0—M7 中增加一步，专门设计前端页面，并澄清指软件页面的设计（R18/S9）

## 背景

现有技术方案列出了页面最小功能，但未设置单独的软件 UI 设计工作包；M1 已有早期界面实现。用户要求设计软件页面本身，故本阶段需要实际绘制逐屏布局、视觉样式和控件，交付高保真页面稿；技术说明、页面清单和流程图只能作为配套，不能替代页面设计。

## 决定

在 M0 与 M1 之间插入 **M0.5：软件页面 UI 设计**。保留 M0—M7 原编号和含义，既有公告 M2、Python M6、发布准备 M7 及历史记录不改号。编号与具体产物格式是实施补充，不冒称用户指定。

- 范围：Android 的 Provider、Agent、Chat、Knowledge、Skills、Announcements、Settings/About 及其关键子页面；公告管理 Web 页面保持 M2 原有范围，不新增其他用户端平台。
- 核心产物：逐屏高保真页面稿、可编辑源稿、布局/样式标注和组件素材；配套交付设计 token、可点击的软件界面原型、页面到实现的映射，以及用户逐页确认记录。具体路径和要求见 [技术方案第8节](../IMPLEMENTATION_PLAN.md)。
- 入口：M0 完成且需求、领域状态和安全边界明确；本次仅修改阶段规划，不解除 `M0_REMOTE_PENDING`。
- 退出：U01—U06 设计验收与用户方案确认完成，只记设计基线通过，不记真实页面或设备通过。
- 衔接：M1 增加 M0.5 入口条件；M2 使用公告客户端页面设计；M3—M7 实现各自页面并复核适用 U 项。现有 M1 UI 先做差异盘点，再分批对齐，不回滚业务修复或补记设计已完成。

## 替代方案

- 将软件页面设计混在各业务阶段：无法形成逐屏视觉、布局和组件的一致基线，不满足独立步骤要求。
- 将软件页面设计加入末尾 M8：业务界面已经完成后才设计，会增加返工，且偏离设计先行的用途。
- 将新阶段命名 M1，原 M1—M7 整体后移：需要改写大量既有阶段和历史验收引用；采用 M0.5 可清晰插入并保持可追溯性。

## 影响与验证

本次只更新方案、需求、验收、文档索引/核查和 HANDOFF；不创建设计产物空壳，不修改产品代码，不改许可，不提交、推送或部署。真实 UI 设计在独立阶段执行，视觉选择届时由用户确认。

文档验证检查 M0/M0.5/M1—M7 顺序、R18/S9 与 U01—U06 映射、入口依赖、相对链接及 SPDX；实际验证结果见 [HANDOFF](../../HANDOFF.md)。后续实现必须同时保留原 A/K/S/N/L 验收，不能用设计走查替代。
