# ADR 0015：PDF 文字层可信条件与装饰图形

日期：2026-09-28（Asia/Taipei）。状态：本地实现，未提交；独立只读复核未进行，待设备与真实 Provider 验收。

## 背景

用户导入 294 个 PDF（11,896 页），绝大多数是排版书籍，本身有完整文字层。按修复前的解析器，9,437 页需要整页视觉；Provider 响应约占处理时间的大部分，整包耗时因此以小时计。同日的过渡版 `v17` 只为首个 174 页样本补齐了少量字形名和“长细水平分隔线”规则，该样本降到 20 页，但同系列其它书仍接近全部视觉。整包统计显示主要原因有四：

1. 字体 `/Differences` 中出现任一未收录的字形名（如 `acircumflex`、`dollar`）时，整个字体被判为未知，包括页面未使用的名称。
2. 带 `/ToUnicode` 的字体及全部 `Type0` 字体一律视为未知，而 Word、InDesign、LibreOffice 等导出的 PDF 基本都属此类。
3. 文字提取器没有登记变长的 `sc`/`SC`/`scn`/`SCN` 颜色算子，只要页面设过颜色就判为文字不完整。
4. 只要页面有任何矢量路径就需要整页视觉，而排版书的矢量内容多为脚注线、分隔线、表格线、白色或整页背景和裁剪路径。

## 决定

指纹升为 `pdf-text-v18-pdfrenderer`，旧解析结果重新计算。

- 字形名按 Adobe Glyph List 规范的算法解析（后缀、连字、`uni`/`u` 形式），名称表采用 ISO 32000-1 附录 D 的拉丁字符集，重音字母用 Unicode 规范合成得出；表内数据由规范事实生成，未复制第三方数据文件。未知名称只使该代码未知，按实际显示的字节决定页面是否完整。
- 解析 ToUnicode CMap 的 `bfchar`/`bfrange`，作为简单字体和 Identity 编码 `Type0` 字体的唯一文字来源；缺失或无意义的目标使该代码未知，`usecmap`、CID 区段、畸形或过大 CMap 使字体未知。非 Identity 的 CID 编码仍需视觉。
- 登记 `sc`/`SC`/`scn`/`SCN` 的变长操作数。
- 文字完整且无图片、可见批注时，若全部绘制路径都是细（≤2 pt）的轴对齐线或矩形边框、细填充条、白色矩形、覆盖页面 90% 以上的背景矩形或纯裁剪路径，且绘制路径不超过 96 条，则不再请求整页视觉。
- 无外观流且 `/BS /W 0` 的 Link 批注视为不可见；`sh` 渐变计入矢量绘制。

## 接受的风险

- 删除线、下划线等装饰线的语义不会进入索引，只保留文字；v17 原先以 Type1 字形边界排除穿字横线，v18 取消此条件，因为多数 PDF 的字体无法给出可靠字形边界，保留该条件会让表格线和脚注线仍全部走视觉。
- 白色矩形遮盖的文字（非规范的遮挡式涂改）会进入索引。
- 由线段拼成且全部轴对齐的简单框图，连接线的含义会丢失，只保留文字标签；超过 96 条路径的页面仍走视觉。
- ToUnicode 本身错误（生成软件写错映射）时文字会错误；独立解析器使用相同映射，比对无法发现这类错误。

## 替代方案

- 保留 v17 的狭窄规则：同系列其它书籍几乎不受益，不能解决用户问题。
- 让所有带文字层的页面都跳过视觉：会遗漏真实矢量图表与插图，违反“含图资料必须经过视觉处理”的约束。
- 对重复图片、Form XObject 和加密 PDF 继续优化：属于独立工作，未在本 ADR 实施；重复图片随后由 [ADR-0016](0016-vision-exact-duplicate-reuse.md) 处理。

## 验证证据

`DocumentParserTest` 新增字形名、未知字形局部化、ToUnicode（含 Flate 压缩、数组 bfrange、代理对）、非法映射、颜色算子、装饰图形正反例和 Link `/BS` 的正反例；`:shared:knowledge-api:test`（218）与 `:data:sqlite:test`（336）严格离线、无构建缓存通过。整包本地解析与独立 PDF 解析器的逐页文字比对见 [专项证据](../evidence/2026-09-28/pdf-text-fast-path.md)。未做真实 Provider、物理设备或整包耗时验收。
