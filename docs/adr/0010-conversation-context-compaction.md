# ADR-0010：会话上下文自动压缩与完整请求预算

日期：2026-09-11（Asia/Taipei）。关联 R34、C20—C25。实现及验证状态见[本轮证据](../evidence/2026-09-11/context-compaction.md)。

## 背景

旧实现按最近用户轮裁剪历史，超过消息条数的一整个长轮会被排除；没有持久化摘要。Chat 和 Runtime 的两份输入估算只计算正文、图片和部分 schema，遗漏实际发送的 `toolCalls.argumentsJson`。相同正文下，约 65 KiB 的工具参数不会相应增加原估算。单个 Run 的八次模型请求上限也不能通过压缩续跑。

## 决定

1. `ModelAdapter.estimateInput` 是准备阶段及每次 Runtime 请求的统一入口。计算正文、角色、工具调用 id/name/完整参数、toolCallId、工具 schema、参数层、协议预留、图片预留，以及该适配器实际回送的私有续接大小。使用 Long 饱和运算；估算单位和 Provider usage 分开。UTF-8 字节及固定图片预留不是精确 tokenizer，也不保证所有 Provider 的视觉计量。
2. 输入上限取 Agent 预算与模型窗口扣除输出预留后的较小值；输出预留至少为模型输出上限。默认开启自动压缩，85% 输入压力、20 条历史消息、10 个历史用户轮或当前段第 8 次普通模型请求触发；目标为 60%，保留最近 2 个历史用户轮。输入预算未指定时采用模型可用窗口。设置保存在 `contextPolicyJson`，通过不可变会话快照生效；修改 Agent 后须新建会话。
3. 每次正常模型派发前统一检查。保留 Runtime/系统/Skill/当前检索块、最初用户目标、当前用户消息、最近完整用户轮、当前最新工具交换、全部图片和 Provider 私有续接；工具调用与其全部结果保持原子关系。最老的可压缩完整单元进入摘要请求，不能截断工具 JSON。无法容纳的固定内容或单个不可分割交换明确 `CONTEXT_OVERFLOW`，保留原文并停止；本版不做长参数分块摘要，也不假装看过未发送的图片。 候选以完整用户轮为单位：被固定的轮（如最初用户目标所在轮）整轮保留，部分固定的当前轮只压缩自包含的完整工具交换，因此不会再出现只覆盖孤立 assistant 回复、注定产生空摘要的付费请求。结构合法但没有任何非空条目的摘要仍按失败关闭，并在 stop reason 记录可诊断分类；不静默删除历史。
4. 摘要采用同一会话模型和 Provider，无工具、无继承的工具选择参数，输出上限默认 1024。仅接受五个字符串数组字段 `goals/constraints/decisions/pending/results`，拒绝未知字段、空摘要、工具请求及超长结果。前一份有效摘要与新增来源合并。摘要作为标明不可信历史数据的 assistant 消息注入，不进入 system，不授予能力，也不会执行或重放任何历史工具。
5. v18 新增 `context_compactions`。记录绑定 conversation/snapshot/run、模型与授权指纹、有序来源消息 ID、来源内容 hash、摘要输入 hash、版本和 parentId、触发原因、前后估算、Provider usage、时间与状态。来源须为该会话的完整持久消息；成功替换前再次校验来源与当前成功链头。同会话仅一个进行中尝试，终态不可改写。原 Message 和工具结果不删除、不覆盖。
6. 状态为 `PREPARED → DISPATCHED → SUCCEEDED / FAILED / UNKNOWN_OUTCOME`；未派发可 `CANCELLED`。先持久化派发标记，再调用 Provider；验证完成后先持久化成功，再替换工作上下文。重启将 PREPARED 取消、DISPATCHED 标 UNKNOWN_OUTCOME，不自动重发。失败/无终帧/取消/超时不使用半成品摘要，不自动重试收费请求。
7. 复用仅限最新成功摘要且会话、快照、模型/授权指纹和来源内容均匹配。摘要失效时从原始完整历史重新准备；授权撤销、知识来源删除仍失败关闭，不能借重新摘要恢复访问。旧摘要链头仍作为新尝试 parentId，避免陈旧尝试覆盖新成果。
8. 段轮数在成功压缩后清零；Run 总请求数（含摘要和 Skill 内模型调用）、工具次数、总时限不清零。自动压缩默认总请求 32、摘要请求 8，仍保留工具 20 次和 180 秒总时限。摘要 usage 累加到 Run，单独显示压缩次数与记录；不承诺无限执行。总请求硬上限独立于自动压缩开关，始终使用会话策略配置（默认 32）；关闭自动压缩仅停止摘要并保留完整轮裁剪。已观察到的摘要 usage 随尝试终态保存，由聊天层按尝试 ID 差额入账；取消导致终态事件未送达时，在不可取消的收尾中从 SQLite 补齐，既不推测未知用量，也不重复累计。
9. 聊天界面提供摘要记录及来源原文入口，标明模型、触发原因、前后估算和摘要 usage。秘密只经过原有凭据路径，摘要正文不进入诊断；Provider 私有续接从不进入摘要、预览或持久化。

## 替代方案与限制

- 仅继续裁剪：无法保存长期任务与决策，且长轮可能被整体遗忘。
- 无限重置 Run 预算：可能导致无界成本、工具执行和失败循环，未采用。
- 更换便宜摘要模型：增加跨 Provider 外发和配置边界，本版采用当前模型。
- 模型拒绝超窗后再反复重试：结果与费用难以判断，本版依赖保守预检；Provider 自身拒绝仍按明确错误处理。
- 摘要是有损文本，结构校验不能证明模型完整保留每项事实。保留原文、近期轮和初始用户约束用于追溯；实际模型摘要质量仍须后续显式授权的 Provider 验证。
- 导入导出继续携带原始会话消息；压缩记录是本地派生状态，不作为可跨实例复用的权限或执行凭证。导入会话从其完整原文重新准备。

## 验证

历史条数和用户轮数压缩也采用 targetPercent（默认 60%）作为回落目标，在保留固定/近期内容的前提下留出后续追加空间，避免刚低于触发线就停止而在下一次发送再次付费压缩。

覆盖完整参数预算的首次/后续请求、超 20 条历史摘要、多次压缩、段轮续跑与总预算、图片/私有续接/工具原子关系、无效摘要、失败/取消/超时、迁移与重启、来源变化/跨会话/陈旧 parent、配置保存和摘要显示。独立只读协议审阅为必要门禁；JVM、Android 编译、模拟器与真实 Provider/真机分别记录，不用本 ADR 代替测试证据。
