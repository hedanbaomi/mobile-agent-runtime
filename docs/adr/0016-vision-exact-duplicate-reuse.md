# ADR 0016：插图单独视觉与完全相同请求的结果复用

日期：2026-09-28（Asia/Taipei）。状态：本地实现，未提交；独立只读复核未进行，待设备与真实 Provider 验收。

## 背景

在 v18 解析下，用户 294 个 PDF 仍有 2,941 页需要视觉。其中同一张图片反复出现：课程封面图在 162 个 `ade-*`/`ini-*` 文件中各出现一次，另一张页眉图也是 162 次，`mystagogus-online.pdf` 有一张小图出现在 35 页。按内容哈希统计，893 次图片出现只有 410 种不同内容。这些页一律整页渲染后发给 Vision，每页的渲染结果都不一样，无法复用。原有“原生文字 + 只发插图”的路径在整包中 0 页生效，因为它要求图片宽高缩放相同、外层不能有嵌套变换、页面不能有任何装饰线或颜色算子，文字对象内也不能设颜色。

用户要求重复图片的判断必须严格：相似度低于 95% 的两张图片不得视为同一张。

## 决定

1. 解析指纹升为 `pdf-text-v19-pdfrenderer`。插图单独处理的条件改为：文字与内容流完整；除图片外的标记都满足 ADR-0015 的装饰图形规则；图片按设备坐标无旋转、无翻转、完全位于 MediaBox 内（容差 0.5 pt，允许宽高不同的缩放和嵌套 `cm`）；页面资源中的每个 XObject 都被绘制；没有可见批注、`/Rotate`、页面裁切框、内联图、文字裁剪（`Tr` ≥ 4）；页面用到的每个 ExtGState 都能解析，且无软遮罩、透明度小于 1、非 Normal/Compatible 混合或传递函数。每张图片须为独立 JPEG，颜色空间为 DeviceRGB、DeviceGray 或一/三分量 ICCBased，不带 Mask、SMask、Decode、DecodeParms、ImageMask、Alternates、Matte。满足时文字直接入索引，只把图片送 Vision；装饰线不再使该页成为缺失证据。
2. `VisionInput.duplicateKey` 由图片请求字节的 SHA-256、随附文字的哈希、溯源提示、目标模型指纹和 prompt/schema/预处理版本组成，只排除页码与小节名。某个请求成功后，同一进程内出现相同 `duplicateKey` 的请求直接采用该成功结果，按新单元保存结果和页码归属，不再派发，诊断事件记为 `vision_duplicate_reused`。只复用 SUCCESS，不复用 UNKNOWN 或失败。
3. 判断同一图片只用字节完全一致（SHA-256），不做感知哈希或近似比较。字节相同即 100% 相同，满足“相似度低于 95% 不得合并”的要求；只差一个像素的图片也会分别请求。

## 接受的代价与风险

- 复用索引只存在进程内。进程被系统回收后，已处理过的图片再次出现时会重新请求一次，此后再复用。持久化索引需要新数据表和迁移，本次未做。
- 请求提示中含页码和小节名，复用结果来自第一次出现的位置。模型描述里偶尔可能提到原页码；引用归属仍按新单元页码。
- 三个文件并行时，同一张图可能在第一个结果保存前被同时派发，只会多请求，不会误用。
- 一页有多张各不相同的图片时，拆分后请求数会多于整页一次；整包估算中这一项只多约 20 次，换来每张图更完整的分辨率。
- 同一图片解码后重新编码为 PNG 的结果须一致才能复用。同一设备、同一版本内是确定的；若不一致，只会失去复用，不会误合并。

## 替代方案

- 近似图片判重（感知哈希、SSIM）：可覆盖重新编码的同一图片，但阈值判断会引入误合并风险，且需要平台解码器；本语料中重复图片均为字节相同，收益很小。
- 以原始 JPEG 字节而非发送字节判重：发送前的解码与缩放结果才是模型实际看到的内容，以发送字节判重更直接。
- 持久化判重表：跨重启复用更完整，但需要迁移并经过独立审阅，留作后续。

## 验证证据

`DocumentParserTest` 新增插图路径正例（装饰线与颜色算子、嵌套变换、非方形缩放、裁剪路径与标记内容、ICCBased N=3、安全 ExtGState）与反例（翻转、旋转、越界、彩色面板、曲线、文字裁剪、CMYK、SMask、ICCBased N=4、页面旋转、可见批注、透明度/软遮罩/混合/传递函数 ExtGState、未声明的 ExtGState）。`KnowledgeRepositoryTest.onlyByteIdenticalIllustrationsReuseOneVisionResult` 先红后绿：同一文档两页同图只请求一次，另一文档同图不再请求，只差一个像素的图片另行请求，两份文档的检索结果都带正确页码。整包本地估算：521 页改为只发插图，593 次插图请求中 210 种不同内容，总请求由 2,941 降至约 2,630。未做真实 Provider、物理设备或整包耗时验收。
