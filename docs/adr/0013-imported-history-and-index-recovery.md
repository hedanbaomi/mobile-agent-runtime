# ADR-0013：导入历史的本机凭据与索引恢复边界

## 背景

`8d97dc0` review 包的设备报告显示：恢复后的冻结会话因无可用密钥引用而在运行准备阶段失败；导入文档的旧 READY 代际可能遮蔽当前活动版本的 chunks；缺源内容时手动重建仍可能报告成功。另有旧格式导入后无关 Agent 历史消失的设备报告，当前导入实现与合成旧格式测试未复现物理删除。

## 决定

1. 保留冻结快照的模型、提示词、资源、权限和持久字段。导入快照标记需要本机凭据时，只允许在运行时从**同 ID、同 API 格式、同 Base URL**的本机 Provider 取得 secret 引用；目标或凭据不匹配则明确拒绝，不猜测其他 Provider，也不把新 secret 写回旧快照。
2. 本地索引修复以当前活动文档版本的 chunks 为真值，READY generation 必须准确覆盖这些 chunks。手动整库重建时，只有非终态导入任务能暂时解释无活动版本的文档；失败或取消的任务不能放行“完整重建成功”。正常单文档发布可暂时忽略正在发布的自身及其他终态失败文档，让已就绪文档保持可检索。缺少可重建的本地源且 generation 已失配时撤销 READY 指针；手动及 API 重建在派发前失败，不发布零向量“成功”。
3. JSON 与 ZIP 导入均在同一 SQLite 事务中暂存已有 Agent 历史记录的 ID 和归属，提交前检查快照、会话、消息、消息部分、Run、工具记录及审计记录。已有 ID 消失或转移归属时抛错并回滚；同数量替换不能绕过。导入结果向用户显示。此校验是防御边界，尚不能解释报告中旧备份的具体删除原因。
4. 会话内容独立 ZIP 条目沿用 32 MiB 条目预算；manifest 继续受 16 MiB 元数据预算约束，避免为大历史放宽 manifest 解析上限。

## 替代方案与影响

直接改写旧快照的 Provider secret 会破坏历史边界且可能把凭据发往变更后的地址，因此不采用。仅以 generation 成员数是否非零判断索引健康，会把旧代际当成当前文档的索引，因此改为集合覆盖检查。缺源 chunks 的元数据备份不能通过索引算法恢复正文，必须使用完整内容备份或重新导入文档。

JVM 测试覆盖旧 JSON/ZIP 数据隔离、事务异常回滚、正文删除与同数量会话替换、历史凭据匹配、>16 MiB 会话往返、代际失配、失败导入后的部分重建拒绝及缺源 fail-closed。用户确认报告所用的旧版备份原件已无法取得；这道回滚保护不能证明原设备数据消失的根因已找到。真实服务商和新包设备复测仍是独立验收项。
