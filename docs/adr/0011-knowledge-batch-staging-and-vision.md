# ADR 0011：批次暂存、固定视觉授权与未知请求恢复

日期：2026-09-13（Asia/Taipei）。状态：本地实施；按用户要求不推送本文。

## 背景

逐文件授权绑定整库可变状态，会被同批次正常发布作废。只改批次 UI 仍不足：文件尚未复制完就允许 Worker 运行、重启重新打开已变化的 ZIP、网络请求未落标记就派发，都会破坏恢复边界。

## 决定

开始导入时显示目标、资料与费用，一次确认选定批次。Schema 20 用 staging_manifest 保存有序来源和目标，以 staging_complete 栅栏区分未完整暂存与可处理批次；只有全部成员冻结之后才建立 vision_scope_hash。授权绑定批次成员键和资料 blob hash，不随 active_version_id 正常变化而失效；目标改变必须重新确认。

ZIP 先落应用私有、同步完成的不可变快照，再展开条目；恢复复用同一快照。普通文件按来源标识幂等，不能以显示名合并。未完成暂存不自动进 Worker，进程恢复后提供明确继续入口。用户 PAUSED 保持暂停；新派发停止，已在途请求可以收尾保存。

Vision 在调用 backend 之前保存 UNKNOWN_OUTCOME；成功再替换为可复用检查点。重启遇到未知结果不会静默重发。用户明确接受重复收费风险且目标与资料复核通过后才可重试。

## 替代方案及代价

不采用继续逐文件授权：无法满足一次批次处理与大列表的交互要求。不采用每次恢复重开外部 ZIP：无法保证中途文件改变后仍属同一批资料。不强行取消已发网络请求来表示暂停：无法据此确定服务端是否计费。私有快照消耗额外暂存空间，读取依然受归档和条目大小上限约束，成功完成暂存后回收快照。

## 验证

独立 DSH 静态复核覆盖授权作用域、派发标记、恢复栅栏与不可变快照；JVM、Android 设备和真实 Provider 验证结果见 [复核报告](../evidence/2026-09-13/p1-batch-import-review.md)。物理设备差异及 294 PDF 全量视觉费用验收保持单独状态。
